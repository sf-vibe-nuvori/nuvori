# Nuvori 진행 방향 (Roadmap)

작성일: 2026-11-26 · 상태: 초안 (팀 리뷰용)

> 영수증 한 장으로 집에 뭐가 있는지 알고, 안 사도 되는 건 안 사고, 있는 재료로 요리하게 돕는 장보기 앱.

## 1. 지금 어디까지 왔나

| 영역 | 현재 상태 |
|---|---|
| `web/` | iPhone PWA 단일 앱 (`index.html`). 인벤토리 · 쇼핑 리스트 · 영수증 검수 · 챗 · 레시피 매칭이 동작. `https://nuvori.netlify.app` 자동 배포 |
| `model/` | 3-State HSMM 소진 예측 엔진 + 테스트 스위트 + 몬테카를로 시뮬레이션. `updateCycleDays`로 구매 주기 갱신 |
| `api/` | Netlify 서버리스 함수: Gemini 영수증 OCR(`parse-receipt`), 장보기·요리 어드바이저(`chat-advisor`) |
| 데이터 | **서버 DB 없음.** 브라우저 `localStorage`(`nuvori_poc_state_v2`)에만 저장 → 기기·브라우저 간 공유 안 됨, 백업 없음 |
| `db/` | Supabase 전환용 마이그레이션 초안(`0001_init.sql`) + 매핑 문서. 계약 변경 제안 3건 **승인 대기** (`db/CONTRACT_CHANGE.md`) |
| `mobile/` | Expo 스캐폴드 (더미 데이터, HSMM·저장·OCR 미연동) |
| 디자인 | v2 레이아웃 적용 PR 오픈 — [#5](https://github.com/sf-vibe-nuvori/nuvori/pull/5) |

각 항목은 **새 데이터 필드 → 계약 변경**이 필요하므로 단계 2와 함께 설계한다.

| 기능 (Figma) | 필요한 데이터 |
|---|---|
| 보관 위치 필터 (냉장/냉동/실온) | 품목별 `storage` 필드 (OCR 추론 또는 사용자 지정) |

| 월간 절약액, "이번 주" 집계 | 날짜별 절약 이력 (현재 절약액은 지금 시점 스냅샷) |
| 남은 양 "~½ bag", "~400 g / week" | 수량·단위 정보 (현재는 구매 주기만 있음) |

## 4. 일하는 방식

- 디렉토리별 담당 에이전트가 **자기 디렉토리만** 수정 (루트 `CLAUDE.md` §1)
- `contracts/`는 읽기 전용. 변경은 사용자 승인 후 관련 디렉토리 전부 함께 갱신
- 기능 개발은 브랜치 → PR. **API 호환성 수정(모델명 deprecated 등)은 `fix-api` 브랜치**
- UI 규칙 원문은 `web/CLAUDE.md` (3종 배지, 게이지바 금지 + 소비 패턴 예외)
- Figma MCP는 월 한도가 있으므로 화면당 `get_design_context` 1회만 사용하고 나머지는 문서 기준으로 진행

## 5. 열린 질문

1. 서버 DB 전환을 언제 시작할지 — v2 머지 직후 vs 사용자 피드백 수집 후
2. 레시피를 계속 코드에 둘지, DB/외부 소스로 옮길지
3. 화면 문구 영어 전환 여부 (현재 한국어 유지, 해외 사용자 대상이면 재검토)
4. 가족·동거인 공유(한 인벤토리를 여러 명이 쓰기)가 목표 범위에 들어가는지
